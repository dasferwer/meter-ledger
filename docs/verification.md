# Результаты проверки

Проверено 13 сентября 2026 года, 02:58 по Москве. Полные результаты и SHA-256 исходников сохранены в [verification.json](verification.json).

- **39 тестов прошли** с отдельной PostgreSQL 17: настоящими транзакциями и ролями БД.
- **HTTP smoke прошёл.** Из 30 одновременных повторов запроса записалось одно событие. Поздний расход не изменил исходный счёт, нулевая корректировка сохранилась, исправление дало −1 цент. Все три ревизии воспроизвелись, повторный расчёт неизменившегося периода вернул существующий счёт.
- **Три проверки восстановления прошли.** Остановка RabbitMQ не потеряла расход и запрос на счёт. SIGKILL worker до commit откатил транзакцию, после перезапуска расчёт завершился. Падение диспетчера между publisher confirm и отметкой в БД привело к повторной публикации без второго счёта.
- Код установленного приложения совпал с локальными исходниками по SHA-256. OpenAPI совпал с живым API; количество передаётся строкой, схемы доступа клиента и администратора присутствуют. HTTP-метрики доступны.
- Два повторных запуска seed сохранили хеши истории клиентов, тарифов, событий, счетов и задач.
- API, PostgreSQL, RabbitMQ, worker и диспетчер находятся в состоянии `healthy`. Приложение работает от UID 999 на Python 3.12.14, без pytest и Ruff в runtime-образе. Тестовая БД остановлена. Среди нумерованных проектов портфолио запущен только MeterLedger.

На локальном стенде выпуск счёта занял **118,57 мс**, включая постановку задачи и опрос результата с интервалом 100 мс. Для 50 последовательных запросов чтения p50 составил **1,85 мс**, p95 — **2,39 мс**. Клиент работал внутри контейнера API и обращался к его loopback; среда — Docker Linux aarch64 на Mac arm64. Это один локальный прогон; нагрузочный тест и SLA не заявляются. Кластерная отказоустойчивость, реальная оплата и работа внешних провайдеров здесь не проверялись.

GitHub Actions ещё не запускался: проект пока сохранён локально. Для повторной проверки доступны `make test`, `make smoke` и `make recovery`; сценарии восстановления временно останавливают процессы этого стенда и затем возвращают их в рабочее состояние.
