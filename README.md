# MeterLedger

[![Проверки](https://github.com/dasferwer/meter-ledger/actions/workflows/ci.yml/badge.svg)](https://github.com/dasferwer/meter-ledger/actions/workflows/ci.yml)

Биллинг SaaS с оплатой по использованию. Сервис принимает измеренный расход, выбирает тариф по времени события и выпускает месячный счёт с объяснением каждой позиции. Поздние события и исправления создают отдельные корректировки. Любой выпущенный счёт можно заново рассчитать из журнала и сравнить с сохранённым результатом.

Главная задача проекта — сохранить корректность денег при повторах запросов, смене тарифов и частичных отказах. Это задание №12 исходного плана портфолио, папка №21.

## Запуск

Нужен Docker Compose. Для локальной разработки и проверки восстановления — Python 3.12 и uv.

```bash
make up
make test
make smoke
uv sync --extra dev --frozen
make recovery
```

API и Swagger: **http://localhost:8210/docs**. API слушает только loopback хоста, база и брокер не публикуют порты. Пять рабочих сервисов: API, worker, dispatcher, PostgreSQL и RabbitMQ. Контейнер `migrate` завершается после миграции и seed. Тесты используют отдельную PostgreSQL в tmpfs.

В Swagger нажать **Authorize**:

| Назначение | Заголовок | Локальное демо-значение |
|---|---|---|
| Клиент | `X-API-Key` | `ml_local_demo_meterledger_customer_change_before_deployment` |
| Администратор | `X-Admin-Token` | `local-demo-meterledger-admin-change-before-deployment` |

Администратор создаёт изолированных клиентов через `POST /admin/tenants`. Случайный ключ возвращается один раз; в базе сохраняется его хеш. Демо-ключ известен заранее и подходит только для локального стенда.

## Пример

Принять 500 API-вызовов за январь 2024 года:

```bash
curl http://localhost:8210/events \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: ml_local_demo_meterledger_customer_change_before_deployment' \
  -d '{"event_id":"demo-january-usage","metric":"api_calls","quantity":"500","occurred_at":"2024-01-15T00:00:00Z"}'
```

Повтор того же события вернёт прежнюю запись с HTTP 200; новая запись возвращает 201. Тот же `event_id` с другим содержимым даст 409. Десятичные значения передаются строками.

```bash
curl http://localhost:8210/billing/issue \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: ml_local_demo_meterledger_customer_change_before_deployment' \
  -H 'Idempotency-Key: demo-january-invoice' \
  -d '{"period":"2024-01"}'
```

Ответ 202 содержит ID задачи. `GET /jobs/{id}` вернёт `invoice_id` после обработки. Сам счёт доступен через `GET /invoices/{id}`, повторный расчёт — через `GET /invoices/{id}/verify`, исходные события — через `GET /invoices/{id}/events`.

При начальном тарифе $0.00001 эти 500 вызовов дают 1 цент после округления. Если добавить ещё 100 поздних вызовов и запросить выпуск с **новым** `Idempotency-Key`, появится ревизия с нулевой доплатой: накопленная сумма всё ещё равна 1 центу. Старый ключ всегда возвращает прежнюю задачу.

## Что реализовано

- Неизменяемый журнал потребления и исправлений, защита от повторов и конфликтующих ключей.
- Три метрики: API-вызовы, ГБ-часы хранения, секунды вычислений. Значения измеряет клиент.
- Версии тарифов с точным временем начала действия. Цена фиксируется в принятом событии.
- Десятичная арифметика, округление до центов по группе тарифа, отрицательные и нулевые корректировки.
- Закрытые календарные месяцы UTC; для текущего месяца доступен предварительный расчёт.
- Снимок источников по номеру журнала, версия алгоритма, SHA-256 и повторный расчёт для проверки.
- Фоновые задачи, transactional outbox, publisher confirms, повторная доставка и карантин неверных сообщений.
- Изоляция клиентов, отдельная роль БД для миграций, запрет изменения истории на уровне прав и триггеров.
- OpenAPI, метрики Prometheus, миграции Alembic, Docker Compose, тесты PostgreSQL и GitHub Actions workflow.

## Основные методы API

| Метод | Назначение |
|---|---|
| `POST /events` | Принять расход с внешним идентификатором |
| `POST /corrections` | Уменьшить исходный расход, указав причину |
| `GET /events` | Журнал клиента, курсор `after` по sequence |
| `GET /rates` | Версии тарифов |
| `GET /billing/{period}/preview` | Накопленная стоимость на текущей границе журнала |
| `POST /billing/issue` | Поставить выпуск счёта в очередь |
| `GET /jobs/{id}` | Состояние задачи |
| `GET /invoices` | История документов, курсор `before_id` |
| `GET /invoices/{id}` | Счёт и объяснение начислений |
| `GET /invoices/{id}/verify` | Сверить с повторным расчётом |
| `GET /invoices/{id}/events` | Исходные события конкретного счёта |
| `POST /admin/tenants` | Создать клиента и выдать API-ключ |
| `POST /admin/rates` | Запланировать новую версию тарифа |
| `POST /admin/jobs/{id}/retry` | Повторить failed-задачу после исправления причины |
| `GET /admin/queue` | Очередь, outbox и heartbeat процессов |

`cumulative_cents` — общее начисление за период на этой ревизии. `delta_cents` — новая сумма к начислению или возврату. Суммировать нужно именно `delta_cents`. Суммы указаны в целых центах; количества и цены возвращаются десятичными строками.

## Проверки

`make test` проверяет конкурентные повторы, границы тарифов и UTC-месяцев, округление, исправления, изоляцию клиентов, неизменяемость истории и восстановление транзакций. `make smoke` проходит полный API-сценарий с поздним расходом и возвратом. `make recovery` останавливает RabbitMQ и завершает обработчики через SIGKILL.

Фактические результаты и условия измерений: [docs/verification.md](docs/verification.md).

## Границы версии

Проект использует демонстрационные счета в USD. Реальные платежи, налоги, абонентская плата и ступенчатые тарифы не подключены. Один клиент принимает события последовательно; расчёт его месяца временно блокирует новые записи этого клиента. База и брокер одиночные. Кластерная отказоустойчивость и промышленная пропускная способность не заявляются.

Стек: Python 3.12, FastAPI, PostgreSQL 17, SQLAlchemy, Alembic, RabbitMQ, aio-pika, Decimal, pytest и Docker Compose. Зависимости зафиксированы в `uv.lock` и `requirements.lock`; runtime-образ запускается от непривилегированного пользователя и не содержит pytest/Ruff.

Подробности: [архитектура](docs/architecture.md), [эксплуатация](docs/runbook.md), [объяснение для собеседования](docs/interview.md).
